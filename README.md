# ICT / Smart Money Concepts - бэктест-тулкит

Стратегия: **1H bias (BOS/CHoCH) + 5m liquidity sweep внутри killzone + 5m FVG confluence на вход**,
частичный тейк на 2R + трейлинг остатка. Собрано по итогам пошаговой отладки в чате с Claude -
подробности решений см. в разделе "Известные грабли" ниже.

## Установка

```bash
python3 -m venv ict_env
source ict_env/bin/activate      # Windows: ict_env\Scripts\activate
pip install -r requirements.txt
```

Пакет для торговли и данных в **Т-Банке (ранее Тинькофф)** переехал в официальный репозиторий [opensource.tbank.ru/invest/invest-python](https://opensource.tbank.ru/invest/invest-python) и ставится из реестра Т-Банка:
```bash
pip install t-tech-investments --index-url https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple
```
Или через готовый файл требований:
```bash
pip install -r requirements-tbank.txt
```

Для работы с криптой через `ccxt` (Bitget/Binance/Bybit) этот пакет не обязателен — крипто-стек работает независимо.


## Запуск

1. Открой `config.py`, выбери `DATA_SOURCE`:
   - `"ccxt"` - крипта, без токена, работает из коробки. Меняй `SYMBOL` / `SYMBOLS` / `CCXT_EXCHANGE`.
   - `"tinkoff"` - MOEX. Нужен токен (см. ниже) и FIGI нужного инструмента.
   - `"github_csv"` - готовый исторический CSV, без токенов, самый быстрый способ проверить,
     что всё работает.
2. **Бэктест**:
   - Одиночный инструмент: `python backtest.py` или `python backtest.py --symbol BTC/USDT`
   - Мульти-инструментальный (сравнение пар, выявление расхождений и переобучения):
     `python backtest.py --all`
     или `python backtest.py --symbols BTC/USDT,ETH/USDT,SOL/USDT`
   - С шагом **ИИ-оценки сделок (Google Gemini API / Fallback)**:
     `python backtest.py --ai`
   - С фильтрацией сделок по оценке ИИ:
     `python backtest.py --ai-filter`
   - С фильтром **Killzones (London 07-10, NY 12-15 UTC)**:
     `python backtest.py --all --killzones`
   - С фильтром **SMT-дивергенции (BTC vs ETH)**:
     `python backtest.py --symbols BTC/USDT,ETH/USDT --smt`
   - С фильтром **свипов ликвидности Азиатской сессии (Asian Range High/Low)**:
     `python backtest.py --all --asian-range`
3. **Ежедневный ИИ-анализ дня и поиск упущенных сетапов**:
   - Анализ последнего торгового дня: `python daily_analyst.py --latest`
   - Анализ конкретной даты: `python daily_analyst.py --date 2025-01-15 --symbol BTC/USDT`
   - Формирует отчёты в папке `reports/`:
     - `reports/daily_review_<symbol>_<date>.json` (структурированный файл для агента)
     - `reports/daily_review_<symbol>_<date>.md` (сводка: рыночный режим, аудит сделок, упущенные входы, аудит фильтров и гипотезы).
4. **Визуальный дашборд**:
   - `python dashboard.py` или `python dashboard.py --symbol BTC/USDT`.
   - Строит локальный `dashboard.html` / `dashboard_<symbol>.html` (свечи + FVG + Order Blocks + ликвидность + сделки).
5. **Live и Демо-торговля (Bitget USDT-M Futures)**:
   - Скопируйте `.env.example` в `.env` и укажите ваши Bitget API ключи (`BITGET_API_KEY`, `BITGET_API_SECRET`, `BITGET_API_PASSWORD`).
   - Запуск демо-торговли на всех 5 парах с лучшим фильтром Asian Range (62.6% Winrate):
     `python live_trade.py --all --asian-range`
   - Запуск демо-торговли на одной паре (например, ETH):
     `python live_trade.py --symbol ETH/USDT:USDT --asian-range`
   - Запуск с ИИ-оценкой сетапов перед входом:
     `python live_trade.py --all --asian-range --ai`
   - Запуск на реальном счёте (требует подтверждения "ДА" в терминале):
     `python live_trade.py --all --asian-range --real`

## Быстрая проверка подключения к бирже (перед полным бэктестом)

Прежде чем гонять полный бэктест, стоит проверить, что `ccxt` реально достаёт данные
именно с твоей биржи (имена пар/лимиты у каждой биржи немного свои):

```python
import ccxt
ex = ccxt.bitget()
candles = ex.fetch_ohlcv("BTC/USDT", timeframe="5m", limit=10)
print(candles[-1])  # последняя свеча - если видишь реальные числа, всё ок
```

Если получишь ошибку по символу - у Bitget для фьючерсов/свопов формат пары может
отличаться от спота (например `BTC/USDT:USDT` для перпетуалов). Проверь актуальный
формат в `ex.load_markets()` перед первым запуском.



## Работа с T-Bank Invest API (Т-Инвестиции / Мосбиржа)

### 1. Подготовка и получение токена
1. Перейдите в личный кабинет Т-Банка: https://www.tbank.ru/invest/ -> **Настройки** -> **Доступ к API**.
2. Выпустите **Токен для T-Invest API** (для безопасного тестирования можно выпустить токен для песочницы).
3. Добавьте его в файл `.env`:
   ```env
   TBANK_TOKEN=t.xxxxxxxxxxxxxxxxxxxxxxxxxxxx
   TBANK_SANDBOX=True
   TBANK_TICKER=SBER
   ```

### 2. Проверка подключения и счетов
Запустите диагностическую утилиту:
```bash
# Проверка счетов, баланса и рыночных котировок корзины акций РФ:
python test_tbank.py

# С автоматическим созданием счета в песочнице и начислением 100 000 руб.:
python test_tbank.py --sandbox --fund
```

### 3. Бэктест на исторических данных Мосбиржи
```bash
# Базовый бэктест всей корзины акций РФ (SBER, GAZP, LKOH, ROSN, YDEX, T):
python backtest.py --all --source tbank

# Оптимальный режим: Киллзона Мосбиржи 11:00 - 15:00 МСК (WR 64.3%, PF 2.07):
python backtest.py --all --source tbank --kz-msk 11-15

# Торговля в произвольных часах (например, с 10:00 до 16:00 по Москве):
python backtest.py --all --source tbank --kz-start 10 --kz-end 16 --msk

# Ядро портфеля без аутсайдеров GAZP и T (WR 67.3%, PF 2.41, Max DD всего 4.96R):
python backtest.py --all --source tbank --kz-msk 11-15 --exclude GAZP,T

# Только шорты (наиболее прибыльный режим на коррекциях рынка, WR 68.1%, PF 2.41):
python backtest.py --all --source tbank --kz-msk 11-15 --direction short

# Бэктест конкретных выбранных акций:
python backtest.py --tickers SBER,LKOH,YDEX --source tbank --kz-msk 11-15

# Бэктест одной акции (Сбербанк) только в Лонг:
python backtest.py --ticker SBER --source tbank --long-only
```

### 4. Запуск торгового бота Т-Банка (`tbank_trade.py`)
Бот адаптирован под специфику Мосбиржи: автоматически учитывает лотность акций, шаг цены, расписание торговых сессий и рассчитывает размер позиции по риску от рублевого депозита:
```bash
# Запуск в песочнице (Sandbox) по всей корзине акций РФ с риском 1% на сделку:
python tbank_trade.py --all --sandbox --risk 1.0

# Запуск в песочнице по одной акции (Сбербанк):
python tbank_trade.py --ticker SBER --sandbox --risk 1.0

# Запуск в режиме локальной эмуляции (Paper Trading):
python tbank_trade.py --all --paper

# Запуск на реальном счёте (требует подтверждения "ДА" в терминале):
python tbank_trade.py --ticker SBER --real --risk 1.0

# Просмотр статистики и PnL закрытых сделок:
python tbank_trade.py --stats
```

## Структура проекта

- `config.py` - единый конфиг (тикеры крипты и Т-Банка, таймфреймы, killzones, риск, Gemini API).
- `data_sources.py` - загрузка данных (ccxt / tbank / github_csv) с авто-кэшированием в `cache/`.
- `strategy.py` - логика детекции сетапов (1H bias, 5m sweep, FVG confluence).
- `ict_advanced.py` - расчет диапазонов Азиатской сессии и SMT-дивергенций.
- `ai_evaluator.py` - модуль оценки сетапов через Google Gemini API (или fallback).
- `backtest.py` - симуляция исполнения, мульти-инструментальные тесты, анализ расхождений и метрики.
- `test_tbank.py` - интерактивная диагностика подключения, счетов и котировок Т-Банка.
- `tbank_trade.py` - live/sandbox-бот для Т-Инвестиций с учетом лотности MOEX и рублевого риска.
- `live_trade.py` - демо/live-исполнитель для Bitget (крипто-фьючерсы) через ccxt.
- `daily_analyst.py` - ежедневный квант-аналитик: разбор дня, аудит стопов, сканер упущенных возможностей.
- `dashboard.py` - визуализация Plotly: свечи + разметка + сделки по любому тикеру.

## Совместная работа с Antigravity-агентом (Strategy Copilot)

Вместо опасного авто-редактирования кода скриптом "под капотом", тулкит построен по модели **Quant Copilot**:
1. `python daily_analyst.py --latest` анализирует торговый день и выявляет:
   - Почему были получены стопы.
   - Какие сетапы были отфильтрованы и были ли среди них упущенные тейки 2R.
   - Формирует команду-гипотезу внизу отчёта `reports/daily_review_...md`.
2. Вы копируете эту команду агенту Antigravity прямо в чат, например:
   > *"Antigravity, изучи daily_review за 2026-09-08: протестируй расширение фильтра FVG до 0.008 на BTC и ETH"*.
3. Агент формулирует изменение в коде, запускает мульти-инструментальный бэктест (`python backtest.py --symbols BTC/USDT,ETH/USDT,SOL/USDT`), проверяет, не сломался ли суммарный R и Winrate, и безопасно сохраняет улучшение.

## Известные грабли (то, что мы поймали в чате и здесь уже исправлено)

Если будешь модифицировать логику - держи в голове три вещи, из-за которых
результат может незаметно стать нечестным:

1. **Look-ahead bias.** `smc.fvg()` определяет гэп на баре `i`, используя данные бара `i+1`.
   Вход не может произойти раньше закрытия бара `i+1` - иначе бэктест видит будущее.
2. **Fill price = цена реального касания зоны, а не середина.** При высокой волатильности
   FVG-зона может быть огромной; вход по "середине" абстрактной зоны без проверки, что цена
   туда реально дошла и как именно - даёт нереалистично хорошие/быстрые результаты.
3. **Минимальный риск.** Если стоп оказывается статистически слишком близко к входу,
   комиссия/проскальзывание съедают сделку непропорционально сильно - см. `MIN_RISK_PCT`.

Также: **стоп через Order Block (`STOP_MODE = "ob"`) в этой библиотеке цепляет структурные
блоки без ограничения по масштабу** - на практике стоп получается в разы шире, чем через
sweep-свечу (см. обсуждение в чате: медиана риска 0.27% против 8.8%). Такой широкий стоп
почти никогда не срабатывает на коротком горизонте удержания, что искусственно завышает
winrate. Прежде чем доверять `"ob"`-режиму, добавь свой фильтр на максимальный размер OB.

4. **Пагинация ccxt.** Разные биржи реально отдают разное количество свечей за
   вызов независимо от запрошенного `limit` (Bitget - максимум ~200, даже если
   просить 1000). Останавливаться нужно по признаку "курсор перестал двигаться
   вперёд", а не "пришло меньше, чем просили" - иначе пагинация обрывается после
   первого же запроса, и ты получишь несколько часов данных вместо нужного периода.

## Что ещё стоит сделать до реальных денег

- **Walk-forward валидация** - разбить период на сегменты, проверить стабильность edge во времени
- **Другие инструменты** - если паттерн реален, он должен воспроизводиться не только на одной паре
- **Реалистичные издержки** - `FEE_SLIPPAGE_PCT` в конфиге консервативная оценка, для своей
  биржи/брокера уточни реальный спред и комиссию
- **Малая выборка = осторожность с выводами** - даже 100+ сделок за 1-2 года для интрадей-стратегии
  не гарантирует, что edge не развалится на новых данных

## Live/демо-торговля (`live_trade.py`)

**Обязательно демо сначала.** По умолчанию `DEMO_MODE = True` в `config.py` - скрипт
торгует на демо-счету Bitget (через `enable_demo_trading()`, официальный режим ccxt/Bitget),
реальные деньги не используются, пока ты явно не переключишь `DEMO_MODE = False` и не
подтвердишь это текстом `ДА` при запуске.

### Настройка

```bash
export BITGET_API_KEY="..."
export BITGET_API_SECRET="..."
export BITGET_API_PASSWORD="..."   # Bitget требует passphrase, не только key+secret
python live_trade.py
```

Торгует **фьючерсами** (`SWAP_SYMBOL = "BTC/USDT:USDT"`), не спотом - наша стратегия даёт
и LONG, и SHORT сигналы, а шорт на споте невозможен без маржи.

### Как это работает

Каждые `POLL_INTERVAL_SEC` секунд скрипт: тянет последние ~1000 минутных свечей → считает
ту же логику, что и в бэктесте (bias/sweep/FVG) → если цена **прямо сейчас** находится
внутри найденной FVG-зоны и сигнал ещё не обработан - открывает рыночный ордер с
прикреплёнными stop-loss/take-profit (`params.stopLoss`/`params.takeProfit` в ccxt).
Обработанные sweep-события запоминаются в `live_seen_signals.json`, чтобы не дублировать
вход на одном и том же сигнале.

### Важные ограничения, которые нужно знать

- **Я не смог протестировать этот скрипт вживую** - у меня в песочнице нет сетевого доступа
  до бирж. Логика построена по актуальной документации ccxt/Bitget на момент написания, но
  обязательно сверяй реально выставленные SL/TP в интерфейсе биржи, а не только по логам.
- **Ctrl+C не закрывает открытые позиции** - если останавливаешь бота с открытой сделкой,
  закрывай её вручную или добавь свою логику graceful shutdown.
- **Частичный тейк + трейлинг из бэктеста здесь не реализован буквально** - `live_trade.py`
  ставит фиксированные SL и TP при входе (упрощённая версия). Управление позицией после
  частичного тейка (перенос в безубыток, трейлинг) нужно either добавлять отдельно, либо
  делать вручную, следя за срабатыванием TP на бирже.
- **Размер позиции сейчас фиксирован в USDT** (`POSITION_SIZE_USDT`), не привязан к риску
  в процентах от депозита - это самое первое, что стоит доработать перед реальными деньгами.
